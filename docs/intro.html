Introduction

NestJS Telemetry is a debugging dashboard you add to a NestJS application with one module import. While the application runs, watchers record what it does: HTTP requests and their responses, exceptions, SQL queries, log lines, scheduled jobs, cache lookups, events, mail and entity changes. The application itself serves a dashboard, at /telemetry by default, where you browse those entries as they arrive. If you know Laravel Telescope, this is the same idea for NestJS: no agent to run, no collector, no external service.

Who it is for​

NestJS Telemetry is for developers who want to see what their application did, request by request, while they build and test it: the status and body a client received, the exception behind a 500, the queries and log lines a request produced, the mail it sent. It also works as a shared debugging view on a development or staging server.

It is not an APM product or an OpenTelemetry SDK. It exports nothing: entries stay in the application's memory or in a local SQLite file, and the dashboard reads them from there.

What it records​

Every entry has one of nine types. Each type is captured in one of three ways:

  • Automatic: active as soon as you import TelemetryModule.
  • Watcher call: you hand data to an injectable watcher from your own code.
  • ORM package: you install and register @nestjs-telemetry/typeorm or @nestjs-telemetry/prisma.
TypeWhat is recordedHow it is captured
REQUESTMethod, path, query string, status, duration, client IP, request and response headers and bodies (masked, then cut at 10,000 characters)Automatic. A global interceptor writes one entry per HTTP request when its response ends. See Requests.
EXCEPTIONError class, message, stack trace (up to 5,000 characters), file and line, the request's method and path, causeAutomatic. A global interceptor records any error thrown while a route handler runs (pipes included) and re-throws it unchanged. See Exceptions.
QUERYTypeORM: SQL, statement type, duration, parameters. Prisma: model, action, statement type, duration, arguments, errorORM package. See TypeORM and Prisma.
LOGLevel, message, context, traceWatcher call. TelemetryLogWatcher is a LoggerService that you register with app.useLogger(). See Logs.
SCHEDULEClass and method name, status (completed or failed), duration, error messageWatcher call. You run each job body through TelemetryScheduleWatcher.wrap(). See Schedules.
CACHEKey (ControllerName.handlerName), HIT or MISS, durationAutomatic. A global interceptor records every route handler that returns a value. See Cache.
EVENTEvent name, payload, payload class, handler class and methodWatcher call. You call TelemetryEventWatcher.record() from your listeners. See Events.
MAILRecipients, sender, subject, HTML and text bodies, a text preview, attachment names and sizes, sent or failed, error, duration, message idAutomatic for nodemailer transporters and the MailerService of @nestjs-modules/mailer found among your providers at startup. Watcher call (TelemetryMailWatcher) for any other sender. See Mail.
MODELEntity, action (CREATED, UPDATED or DELETED), entity id, changed fields (TypeORM) or written data (Prisma)ORM package. See TypeORM and Prisma.

Entries recorded while an HTTP request is handled share that request's batch ID, so the dashboard can list everything one request caused next to it. See Batch correlation.

Current limitation
  • Logs, scheduled jobs and events are not captured on their own. The module does not hook into Nest's logger, @nestjs/schedule or @nestjs/event-emitter, so those views stay empty until you wire the corresponding watcher.
  • The cache watcher does not look at any cache. It records a CACHE entry for every route handler that returns a value, the dashboard's own API routes included, and labels it HIT when the handler took less than 2 ms and MISS otherwise.

The versions are the ones in each package's package.json. Both ORM packages require the core package as a peer dependency, in the range ^0.1.0 or ^0.2.0.

How it works​

TelemetryModule.forRoot() returns a global dynamic module. It creates the storage, binds three global interceptors (requests, exceptions, cache), registers the log, schedule, event and mail watchers as injectable providers, instruments the sendMail() of the mail senders it finds among your providers at startup, and mounts a controller at basePath that serves the dashboard page and a JSON API under {basePath}/api, behind a guard that checks the access token when you set one. While a request is handled, the request interceptor keeps a batch ID in AsyncLocalStorage, and every entry recorded in that async context carries it. A background service deletes entries older than pruneHours and flushes the SQLite write buffer. The dashboard is a single HTML page that calls the API every five seconds. Architecture describes each piece.

Requirements​

RequirementDetails
Node.js18 or later. This is the engines field of the repository's root package.json. The published packages declare no engines field, so your package manager does not check it.
NestJS10 or 11. @nestjs/common and @nestjs/core are peer dependencies in the range ^10.0.0 or ^11.0.0, together with reflect-metadata (^0.1.13 or ^0.2.0) and rxjs (^7.0.0). The test suite runs on NestJS 10.
HTTP adapterExpress (@nestjs/platform-express, the Nest default). The dashboard route is written against Express's response object (res.type().send()), and the tests run on Express only. The access-token guard does not depend on the adapter: it reads only the token query parameter and the x-telemetry-token header.
Native build toolsOnly when no prebuilt better-sqlite3 binary matches your platform. See The native SQLite dependency.
BrowserThe dashboard page loads Tailwind CSS from cdn.tailwindcss.com and Alpine.js from cdn.jsdelivr.net, so the browser that opens it must be able to reach both. A Content-Security-Policy that your application sends on every response (from helmet, for example) applies to the dashboard page too.
note

Fastify is not covered by the test suite. Up to 0.2.3, the access-token guard read Express's req.path, which a Fastify request does not have, so on @nestjs/platform-fastify the token protected nothing. The guard no longer looks at the path.

Where it fits​

NestJS Telemetry is built for development and staging. Before you run it anywhere else, know what it does by default:

  • The dashboard and its API are open. With no accessToken, anyone who can reach the application can read every entry and call the API routes that clear entries or pause recording. See Access token and security.
  • It keeps request and response headers and bodies. Credentials are masked by field name and by the shape of a JWT, which does not catch everything. See Data masking.
  • Entries live in memory. The default storage keeps up to 1,000 entries per type, loses them when the process restarts, and holds them separately in each instance of a scaled-out application. Storage covers the SQLite alternative.
  • Each request costs extra work. Text responses up to 256 KB are copied and masked before they are stored.

To keep the package out of production installs, add it as a development dependency: see Development-only setup. If you run it beyond development, go through the Production checklist first.
