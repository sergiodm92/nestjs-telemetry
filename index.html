NestJS Telemetry

A zero-configuration, real-time debugging dashboard for NestJS applications

Inspect requests, exceptions, SQL queries, logs, scheduled tasks, cache operations, events, mail and model changes of a NestJS app, as they happen.

Get startedWhat it records
npm install @nestjs-telemetry/core
app.module.ts
import { Module } from '@nestjs/common';
import { TelemetryModule } from '@nestjs-telemetry/core';

@Module({
  imports: [TelemetryModule.forRoot()],
})
export class AppModule {}

// npm run start, then open http://localhost:3000/telemetry

One import, a full dashboard

TelemetryModule.forRoot() mounts a single-page dashboard and its JSON API next to your routes. No build step, no agent, no external service.

Everything a request did, together

Each HTTP request gets a batch ID through AsyncLocalStorage, so the queries, logs, exceptions and mail it caused are one click away from it.

Masked by default

Credentials are masked by field name at any depth, JWTs by their shape, and query strings of URLs, in requests, responses and mail alike.

Memory or SQLite

Keep the last entries per type in memory, or persist them to SQLite (WAL, buffered writes), with automatic pruning either way.

Nine kinds of entries

RequestsMethod, URL, status, duration, headers, request and response bodies, user and tenant.ExceptionsError class, message, stack trace and the request that raised it.QueriesSQL and Prisma operations with their duration, from the TypeORM and Prisma packages.LogsEvery level written through the Nest logger, filtered by context if you want.SchedulesScheduled task runs: duration, status and the error of a failed run.CacheCache hits and misses of the routes that use the cache.EventsEvent name, payload and the handler that ran.MailEvery nodemailer / MailerService send, rendered, with its status, picked up with no code.ModelsEntities created, updated and deleted, with the changed fields.
